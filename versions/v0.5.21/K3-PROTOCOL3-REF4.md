# Kimi K3 protocol3-ref4: compile lifecycle and bounded failure diagnostics

Cold grammar compilation in protocol3-ref3 cleared the shared native compiler cache after each dispatch. A completed short request could therefore wait for an unrelated long compilation. This release lets completed peers return while the current native batch drains, then performs one cleanup before admitting the next batch.

Compilation reservations occur before the final live-waiter check, including Reasoner wrappers. Fully abandoned work is checked both before and after that admission wait. An abandoned singleflight source stops accepting new waiters under the cache lock; its completion cannot remove a newer same-key source. Existing pending input remains charged until the old source callback finishes. Reentrant compilation shares one reservation, and failed native futures are still cleaned when the batch drains.

The existing Kimi constraint rejection path also gains bounded numeric diagnostics for original explicit strict declarations and fixed keyword classes. The added summary excludes tool names, schema values, references, request text and output text. This does not change validation, strictness, request limits or supported schema shapes. The older exception log remains outside this new summary's privacy guarantee.

Known boundary: rare regex/EBNF native-cache cleanup exceptions now propagate as infrastructure HTTP500 rather than their former HTTP400 classification. Single native working sets, live matchers and allocator retention remain outside cache-charge limits. Cancellation after the final live-waiter check cannot stop native compilation that has already begun.

Source tests, actual installed-image CPU tests, source tag/Release, image publication and production acceptance are separate stages. No production inference probes or load tests were sent in this release chain. Node101 is the only candidate deployment target; node102 independently returns to its own accepted configuration, and nodes103/104 are outside this release's deployment scope. Synthetic CPU checks cannot establish production semantic success, unavailable request-payload coverage, GPU performance or worst-case grammar safety.
